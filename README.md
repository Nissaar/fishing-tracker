# Fishing Tracker Pro

A fishing log for anglers in Mauritius: record trips and catches, see conditions for the day, follow events and a leaderboard. Public site name: nulapess.app. The full production walkthrough (Traefik + Cloudflare) is in [domain.md](domain.md).

## Features

- **Trip and catch logs** with several fishing types; logs from visitors go through an approval step before they count publicly.
- **Conditions**: weather (OpenWeather / WeatherAPI / Open-Meteo), tides, and sunrise, sunset, moonrise and moonset from the official Mauritius Meteorological Services page (scraped with the `meteomoris` library, cached for 24 hours, with a calculated fallback: see [backend/METEO_MAURITIUS_INTEGRATION.md](backend/METEO_MAURITIUS_INTEGRATION.md)).
- **Events** and a **leaderboard**, user profiles, a public landing page and a contact form (Mailgun).
- **Sign-in** with e-mail and password or Google; JWT sessions that can be revoked per user (token version).
- **Admin panel**: users, submissions to approve, statistics; rate limited and audited.

## Stack

React 18 (Create React App, Tailwind) behind nginx · Node 20 + Express · PostgreSQL 15 · Python helper for the Meteo scraper · Docker Compose.

## Run it

```sh
cp backend/.env.example backend/.env   # JWT_SECRET, SESSION_SECRET, DB_PASSWORD, Google sign-in, weather keys, Mailgun, FRONTEND_URL / CORS_ORIGIN
echo 'DB_PASSWORD=change-me' > .env    # the same password, read by docker-compose.yml for Postgres
docker compose up --build
```
Postgres creates its first schema from `init.sql` on an empty volume; the backend applies the numbered files in `backend/migrations/` by itself at start-up and records them in `schema_migrations`, so a restart never replays them. Backend on :5000, frontend served by nginx. The `.env` files are git-ignored: never commit them.

Without Docker: `cd backend && npm install && npm run dev`, and `cd frontend && npm install && npm start`.

## Tests

End-to-end tests with Playwright (pages, auth, dashboard, admin, API; Chrome, Firefox and mobile Chrome): see [e2e/README.md](e2e/README.md) and [e2e/TEST_DOCUMENTATION.md](e2e/TEST_DOCUMENTATION.md). CI runs them (`e2e.yml`), CodeQL (`codeql.yml`) and a production check after every merge to `main` (`post-merge-prod-check.yml`); every push is mirrored to GitLab.

## Layout

| Path | What |
|---|---|
| `backend/src` | `routes/` (auth, fishing, logs, events, admin, public, contact), `controllers/`, `services/` (weather, tides, Meteo Mauritius, leaderboard, submissions), `middleware/`, `models/` |
| `backend/migrations` | numbered SQL migrations |
| `frontend/src` | `components/` (Auth, Dashboard, Profile, Public, Layout), `context/`, `hooks/`, `services/` |
| `e2e/` | Playwright suite and its own Docker test environment |
| `marketing/` | images and text for the Facebook page, generated by `generate-images.py` |
| `deploy.sh` | copies the env files into place before a deploy |
